# КиноКвиз — правила для работы с репозиторием

Браузерная игра для Яндекс Игр: угадать фильм по описанию. Подробности для людей — в README.md.

## Стек и команды

- TypeScript (strict, `noUncheckedIndexedAccess`), Preact 11 + `@preact/signals`, Vite, Vitest. Своего сервера нет.
- `npm run dev` — игра на localhost:5173 с заглушкой площадки (`?fast=1`, `?lang=en`, `?auth=0`, `?ads=fail`).
- `npm test` — тесты. `npm run check` — типы и контент.
- `npm run build` — сборка для Яндекс Игр (с `/sdk.js`, `YandexPlatform`). `npm run pack` — то же + zip для консоли. `npm run zip` — только zip из готового `dist/`. `npm run build:standalone` — сборка с заглушкой.
- Площадка выбирается при сборке через `VITE_PLATFORM` (`.env.*`). В боевой сборке не должно быть кода `LocalPlatform` (проверка: в `dist/assets/*.js` нет строки `MOCK`).
- Перед каждым коммитом: `npm run check && npm test`. Оба должны проходить.

## Архитектура

- `src/core/` — чистая логика: никаких DOM, `window`, SDK и сигналов. Время передаётся параметром. Любая новая логика здесь — с тестом в `*.test.ts`.
- `src/platform/` — всё общение с площадкой только через `IPlatform` (`types.ts`). Код вне `platform/` не обращается к `YaGames`/`ysdk` напрямую. `YandexPlatform` получает SDK через конструктор и тестируется на подставном SDK (`YandexPlatform.test.ts`); типы SDK — `@types/ysdk`.
- `src/state/` — сигналы и действия, связывают core, платформу и UI. Сохранение меняется только через `updateSave()`.
- `src/ui/` — компоненты Preact, без бизнес-логики.
- Баланс (цены, таймеры, очки) — только в `src/core/config.ts`. Товары — в `src/core/products.ts`, их id совпадают с консолью Яндекс Игр.

## Требования Яндекс Игр, которые нельзя ломать

- Цена и иконка валюты покупок берутся только из SDK (`payments.getCatalog`), не хардкодятся.
- Покупки: выдать → сохранить → `consumePurchase`; при запуске обрабатывать необработанные.
- Полноэкранная реклама — только между сеансами, не во время вопроса. Звук выключается во время рекламы и при скрытой вкладке.
- GameplayAPI start/stop вокруг активной игры; `LoadingAPI.ready()` — когда игра готова.
- Никаких внешних ссылок и внешних запросов: шрифты и ресурсы — только из бандла.
- Лимиты SDK: `player.setData` — 100 запросов за 5 минут (облако пишем не чаще раза в 5 с, кроме покупок), `leaderboards.setScore` — раз в секунду, `getEntries` — 20 за 5 минут.
- Перед правкой интеграции сверяться с документацией: https://yandex.ru/dev/games/doc/ru/sdk/sdk-about

## Контент

- `src/content/films.json` — общие данные; `src/content/texts/<язык>.json` — названия, режиссёры, по два описания (лёгкое с зацепками и абстрактное).
- Описания пишем сами. Не копируем тексты Кинопоиска, Википедии и других сайтов, не используем постеры и кадры.
- В описании нет слов из названия и вариантов названия и нет имён главных героев. Длина описания 40–260 символов.
- Новые фильмы добавляются пачкой через `node tools/add-films.mjs пачка.json` (формат — в README), а не правкой трёх файлов вручную.
- `npm run content:check` ловит пропуски, лишние id и слова из названия — запускать после любой правки контента.
- Баланс каталога: смесь мирового, советского/российского кино и анимации; `popularity` 3 — не больше примерно пятой части.

## Локализация

- Строки интерфейса только через `t()`/`tn()` из `src/i18n`. Новый ключ добавляется в `ru.ts` и `en.ts` одновременно (TypeScript проверит).
- Множественное число — формы `{ one, few, many, other }`, без ручных склонений в коде.
- Тексты на русском и английском пишем как живой язык интерфейса, без канцелярита.

## Дизайн

Тема «кинотеатр»: винный зал, бархат, латунь, экран, бумажные билеты. Цвета — только переменные из `src/styles/tokens.css`. Шрифты: Poiret One (вывеска, крупные заголовки) и Manrope (всё остальное). Вёрстка проверяется на 390×844, 844×390 и 1366×820.

## Git

- Сообщения коммитов на русском, в стиле Conventional Commits: `feat(core): …`, `fix(ui): …`, `docs: …`, `chore: …`.
- Маленькие осмысленные коммиты; после завершения задачи — `git push` в `origin main`.
