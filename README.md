# КиноКвиз

Браузерная игра для Яндекс Игр: угадай фильм по короткому описанию. Визуальный стиль — старый кинотеатр: бархатный зал, латунь, вывеска с лампочками, варианты ответа в виде бумажных билетов.

**Стек:** TypeScript (strict) · Preact + Signals · Vite · Vitest. Сервера нет — сохранения, покупки и рейтинг идут через SDK площадки.

## Запуск

```bash
npm install
npm run dev               # http://localhost:5173, заглушка площадки
npm test                  # тесты ядра, контента, локализации и адаптера Яндекса
npm run build             # сборка для Яндекс Игр в dist/ (с /sdk.js)
npm run pack              # build + архив kinoquiz-yandex-<версия>.zip для консоли
npm run build:standalone  # сборка с заглушкой — демо вне Яндекс Игр
```

В режиме разработки игра работает на заглушке площадки (`LocalPlatform`): реклама, покупки и вход показываются как диалоги с пометкой MOCK. Параметры URL:

| Параметр | Что делает |
|---|---|
| `?lang=en` | язык, который «сообщает площадка» |
| `?auth=0` | игрок не авторизован (проверка приглашения войти) |
| `?ads=fail` | рекламу не досматривают (награда не выдаётся) |
| `?fast=1` | реклама и покупки без диалогов и задержек (для автотестов) |

## Публикация в Яндекс Играх

Площадка выбирается при сборке переменной `VITE_PLATFORM` (`.env.development`, `.env.production`, `.env.standalone`). Сборка для Яндекса подключает `/sdk.js` тегом в `<head>` и использует `YandexPlatform`. Путь к SDK можно переопределить переменной `VITE_YANDEX_SDK_SRC`.

**Что настроить в консоли разработчика:**
1. Загрузить архив из `npm run pack` (в корне архива `index.html`).
2. **Лидерборд** с техническим именем `marathon`: числовой, по убыванию, основной. Имя задано в `src/platform/yandex/YandexPlatform.ts` (`LEADERBOARD_NAME`).
3. **Покупки:** включить и создать товары с id из таблицы ниже. Цены задаются в консоли, игра берёт их из SDK.
4. **Языки:** русский и английский. Описание, иконку и скриншоты — для обоих.
5. Проверить игру в режиме отладки (`?debug-mode=16`): моки валюты, рекламы и покупок.

**Как адаптер выполняет требования площадки:**
- `LoadingAPI.ready()` — когда открыто фойе и обработаны необработанные покупки.
- `GameplayAPI.start/stop` — при начале и конце сеанса, а также автоматически на время рекламы, паузы площадки (`game_api_pause/resume`) и скрытой вкладки. Повторные вызовы не отправляются.
- Звук выключается на паузе и во время рекламы. Таймер ответа на паузе не идёт, бонус за скорость не сгорает.
- Сохранение — в `player.setData` под ключом `save` (до 200 КБ) с локальной копией. Облако пишется не чаще раза в 5 секунд, кроме покупок: они сохраняются сразу, до `consumePurchase`.
- Рейтинг — `ysdk.leaderboards`. Счёт отправляется только авторизованным, только при новом рекорде и не чаще раза в секунду. Рекорд, поставленный до входа, отправляется сразу после входа.
- Цена и иконка валюты — из `payments.getCatalog()` (`getPriceCurrencyImage('svg')`).

Локально проверить боевую сборку с настоящим SDK можно через пакет `@yandex-games/sdk-dev-proxy`: он раздаёт `dist/` вместе с `/sdk.js` в режиме разработчика.

## Как устроена игра

- **Марафон.** Вопросы идут подряд, сложность растёт (первые 5 — лёгкие, к 12-му открываются все уровни). Фильмы в сеансе не повторяются, а вопросы, которые игрок уже видел, показываются в последнюю очередь.
- **Хардкор.** Тот же марафон, но без вариантов: название вписывается вручную. Очки ×2, жетоны ×2, на бонус скорости 15 секунд вместо 8; 50/50 недоступна, «Не знаю» — ошибка с показом ответа. Рекорд хранится отдельно и пока не идёт в рейтинг площадки.
- **Сравнение названий** (`core/quiz/titleMatch.ts`) прощает регистр, «ё/е», «й/и», диакритику, пунктуацию и пробелы, ведущий артикль, «часть/part», римские цифры, опечатки (допуск растёт с длиной названия) и ввод не в той раскладке. Принимаются название, `aliases` и части составного названия («Хатико», «Самый верный друг»). Цифры должны совпасть точно, а ответ, который ближе к другому фильму каталога, — ошибка. Если ввод одинаково подходит к нескольким фильмам («Властелин колец»), игрока просят уточнить, билет не тратится.
- **Сложность вопроса** = известность фильма (1–3) + уровень описания (лёгкое или абстрактное). Неверные варианты подбираются похожими: близкий жанр и годы, мультфильмы не смешиваются с игровым кино.
- **Очки:** база по сложности × бонус за скорость (до +50%) × множитель серии (до ×2) × штраф за подсказки.
- **Билеты** (жизни): 5 штук, ошибка стоит одного, +1 каждые 20 минут. Когда билеты кончились, сеанс можно один раз продолжить за рекламу или докупить билеты.
- **Жетоны** (мягкая валюта): за верные ответы, серии, ежедневный бонус и рекламу. Тратятся на подсказки.
- **Подсказки:** 50/50, год, жанр и страна, режиссёр, «второй шанс» (ошибка не сгорает), пропуск вопроса.

Весь баланс — в `src/core/config.ts`.

## Структура

```
src/
├── core/        # логика игры без DOM и SDK: подбор вопросов, марафон, очки, билеты, сохранения
├── platform/    # интерфейс IPlatform, YandexPlatform (SDK) и заглушка LocalPlatform
├── state/       # состояние на сигналах: сохранения, экономика, сеанс, касса, реклама, рейтинг
├── content/     # films.json (общие данные) + texts/<язык>.json (названия и описания)
├── i18n/        # словари интерфейса и реестр языков
├── audio/       # звуки, синтезированные через Web Audio
├── ui/          # экраны и компоненты Preact
└── styles/      # токены палитры, база, компоненты, экраны
tools/
├── add-films.mjs          # добавление пачки фильмов в каталог
├── validate-content.mjs   # проверка контента перед сборкой
└── pack.mjs               # архив dist/ для консоли Яндекс Игр
```

Ядро (`core/`) не знает ни о браузере, ни о Яндексе. Поэтому оно покрыто тестами и может переехать на другую площадку: достаточно реализовать `IPlatform`.

## Контент

Описания написаны специально для игры. Тексты Кинопоиска, постеры и кадры не используются: это чужой контент.

Сейчас в каталоге **200 фильмов**: мировая классика и блокбастеры, советское и российское кино, анимация. У каждого по два описания на каждом языке.

**Добавить фильмы:**
1. Собрать пачку в одном JSON-файле — массив объектов:
   ```json
   {
     "id": "snake_case", "year": 1999, "genres": ["drama"], "countries": ["US"], "popularity": 1,
     "ru": { "title": "…", "aliases": [], "director": "…", "descriptions": ["лёгкое", "абстрактное"] },
     "en": { "title": "…", "aliases": [], "director": "…", "descriptions": ["easy", "abstract"] }
   }
   ```
   `popularity`: 1 — знают все, 3 — для киноманов. Страны — коды ISO, для СССР — `SU`.
   В `aliases` — другие названия, под которыми фильм знают («Инсепшн», «Неприкасаемые»): их примет хардкор. Опечатки и «ё/е» добавлять туда не нужно — их прощает сравнение.
2. `node tools/add-films.mjs пачка.json` — разложит фильмы по `films.json` и текстам языков.
3. `npm run content:check` — проверит, что тексты есть на всех языках, а в описаниях нет слов из названия.

## Локализация

Сейчас есть русский и английский. Язык берётся из площадки: для языков СНГ показывается русский, для остальных — английский. В настройках язык можно сменить вручную.

**Добавить язык:**
1. `src/i18n/locales/<код>.ts` — словарь интерфейса. Можно частичный: недостающие строки возьмутся из fallback-языка.
2. `src/content/texts/<код>.json` — названия и описания фильмов.
3. Строка в `LANGUAGES` в `src/i18n/languages.ts`.

Ключи словаря типизированы по русскому словарю: опечатка в ключе ломает сборку, а у английского словаря TypeScript проверяет полноту.

## Покупки

Товары описаны в `src/core/products.ts`; их `id` должны совпадать с id в консоли Яндекс Игр. Цены и иконка валюты в игре не хранятся: по требованиям площадки они берутся из SDK.

| id | Что даёт | Тип |
|---|---|---|
| `starter_pack` | 500 жетонов, 5 билетов, 3 × 50/50, 2 × второй шанс | расходуемый, продаётся один раз |
| `tickets_5` | 5 билетов | расходуемый |
| `unlimited_1h`, `unlimited_24h` | ошибки не тратят билеты | расходуемый |
| `coins_300`, `coins_1000`, `coins_3000` | жетоны | расходуемый |
| `no_ads` | отключает полноэкранную рекламу | разовый |

Схема обработки: `purchase` → выдать → сохранить → `consume`. При запуске игра проверяет необработанные покупки, а метка выдачи в сохранении защищает от двойного начисления.
